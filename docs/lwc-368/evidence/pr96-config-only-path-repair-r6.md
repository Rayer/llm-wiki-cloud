# LWC-368 PR96 config-only normalizer path repair (r6)

Status: local source repair and scoped verification complete on top of PR96 head `3cb518792668449f87e302416939c1670272a39d`. This report records source and fixture evidence only; it does not claim a new-head CI result, merge, or live DEV acceptance.

## Accepted finding and repair

The formal Supervisor HOLD identified `deploy/engine/pipeline_config_only.py` running the real Go normalizer with `cwd=root/apps/bff` while passing `deploy/environments/{environment}.yaml` as if it were relative to the repository root. The normalizer therefore opened the nonexistent `apps/bff/deploy/environments/...` path for both environments. The adapter now resolves that fixed YAML path under its supplied repository root before invoking Go, matching the general release path.

The new `test_config_only_uses_real_normalizer_with_controlled_providers` exercises the actual adapter for development and production. It synthesizes only the prepare output, launches the real `go run ./cmd/deploy_config` against the real checked-in environment YAML, and controls all provider commands in-process. It checks Worker-only normalization, the environment-specific Job and bucket, GCS object upload/readback and TOML hash, secret binding and timeout readback, unchanged digest-pinned image, and absence of build/push/image flags.
