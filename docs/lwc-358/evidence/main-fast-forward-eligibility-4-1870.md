# LWC-358 required DEV eligibility status restoration

This local-only candidate restores the Actions-owned `main-fast-forward-eligible` commit status retired from the registered `deploy-dev.yml` wrapper. The previous `origin/main` workflow had a job with that exact name, dependent on the DEV deployment, and published the status only after checking the exact candidate SHA, current `develop` head, and `main` ancestry. Branch protection was not changed.

The replacement job reads the `lwc-result-development-<run_id>-<run_attempt>` artifact emitted by the current reusable release workflow. It checks the current attempt's plan, state, and formal result together: the plan must describe the selected Development release; state and result must both be `success`; the result attempt, tag, source, and checkpoint must agree with the plan/state; and the state executor SHA must equal this workflow's `github.sha`. It does not require `source_sha == executor_sha`, so an accepted retained-source recovery can report source `173d290…` while running reviewed executor/head `ce6fb32…`. The readback operation is excluded from the publisher job entirely, leaving any prior status untouched. Failed/unknown current result, missing result artifact, changed develop head, or main not being an ancestor cannot publish success.

The publisher is isolated from deployment credentials: it has `contents: read`, `actions: read`, and `statuses: write`; checkout uses `persist-credentials: false`; GitHub ref reads use the scoped `GH_TOKEN`. No provider or deployment action is called by this job.
