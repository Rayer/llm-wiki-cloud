# LWC-354 bounded metadata slice report

## Delivered

`internal/profiletags` now has strict, bounded immutable decision/set/query-rule JSON; SHA-256 byte revisions; source/concept keys; separate configured/returned model identities with a pinned allowlist; an injected evaluator and immutable store; incremental reuse; finite retry of missing keys; a deep publication validator; and a two-object Query reader. `ReadBundle` checks one active tuple and generation-bound inventory index without raw source reads, per-concept page stats, or decision object reads. `RequireSupported(requestedTagIDs,kind)` reports only requested hard constraints as unsupported; quality-policy approvals are rejected until geo and independent quality evidence are wired. The package does not call Jev, DeepSeek, Cloud Run, Firestore, or GCS by itself.

The exact exported LWC-355 API is in `internal/profiletags/query_reader.go`: `ReadBundle(ctx context.Context, store Store, active ActiveRef, index InventoryIndex, dictionary Dictionary) (Bundle,error)`. `ActiveRef` has `ContentGeneration`, `DictionaryRevision`, `TagSetRevision`, `QueryRuleRevision`. `InventoryIndex` has `ContentGeneration`, `ConceptsDigest`, `IDMapDigest`, `SourceSnapshotDigest`, and `Items []ItemRef`, each `ItemRef` having `Kind`, `StableID`, `ContentDigest`. `Dictionary` has `Revision`, `Tags []Tag`; `Bundle` has `Set`, `Rules`, `RequirementStatus(requested []string,kind Kind) []string`, and `RequireSupported(requested []string,kind Kind) error`. `Store` is Project-scoped `Read(ctx,path,limit)` and create-only `Create(ctx,path,bytes)`; the caller must authorize scope and pin generation before calling it. `ValidatePublication` in `reader.go` is writer-only deep readback.

## Exact integration points and gates

1. **Generation inventory/source snapshots:** LWC-353's `cmd/olw_worker/cloud_publish.go:publishCloudGenerationWithFiles` commits `current.json`; `internal/generation/manifest.go` defines immutable generation files. The integration must create and retain source snapshot bytes and a digest-bound manifest for the generation, validate `cache/raw_status.json` receipts against `cache/id_map.json`, and supply `Inventory` to the Tag writer and `InventoryIndex` to Query. It must enumerate concepts from the manifest-listed `cache/concepts.jsonl` once, cross-check IDs with the manifest-listed `id_map`, and never fall back to mutable raw sources or per-concept scans. This slice accepts a validated injected inventory; it does not fabricate this missing upstream binding.
2. **Deferred dispatch and Job fencing:** `internal/handler/v1/profile.go:SaveProfile` writes `scheduled_for` and a derivation intent; `ClaimProfileJob`, `ProfileJobTransition`, and `activateProfileState` provide the current versioned state seam. The parent coordinates one durable due-work dispatcher for 352 and 354; 352 owns the derivation executor and 354 will add a Tag Job entry using `Build`/`ValidatePublication`. The proposed Cloud Scheduler tick reads due Firestore intents/jobs, verifies service identity and Project metadata, invokes allowlisted Cloud Run Jobs v2 `:run` using the existing pattern in `internal/handler/v1/endpoints.go:invokePipelineJobStage`, and persists/reconciles execution leases. The 209 Job claim currently treats `running` as idempotent without a lease; add execution fencing and artifact readback before passing `coverageComplete=true`. No scheduler or Job stub is falsely marked implemented.
3. **Exact-generation Query:** `internal/gcs/client.go:PinCurrentGeneration` pins only current `current.json`; LWC-355 needs a by-generation pin with retention, or LWC-353 must gate publish until Tag coverage/active CAS can move atomically. Query must build `InventoryIndex` from that exact pinned manifest/index and call `ReadBundle` once per request. Retain old G1 generation and source snapshots while active still names G1 after G2 publish.
4. **Provider and policy:** The parent chose Jev direction from LWC-334/349. The 334 report records requested `jev-latest` and observed returned `jev-1.13.0` on 23 actual calls, with insufficient independent holdout for hard quality gates. A real Jev adapter, explicit accepted model policy, transport/error mapping, and provider call budget are still needed; the `internal/llm` metadata method is owned by 352. No model-only geographic hard gate is enabled. A later reviewed quality policy must classify deterministic geo evidence before any required gate is considered.
5. **Deployment:** `deploy/environments/development.yaml` and `production.yaml` define existing pipeline Jobs, while `deploy/components/worker.sh` only updates their image. A Tag Job/image/config, shared Scheduler target, runtime identity, exact Run invoker/Firestore/GCS/Secret Manager IAM, and readback must be reviewed and provisioned separately. No cloud mutation, credentials, commit, push, or deploy occurred here.

Whole LWC-354 remains incomplete until these integration gates, real Jev provider evaluation, exact-version LWC-355 consumption, and DEV end-to-end evidence are delivered. The current package can be reviewed and integrated without claiming those outcomes.
